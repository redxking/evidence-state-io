# Support

Evidence-State I/O is a pre-alpha research prototype maintained on a best-effort basis.
There is no service-level agreement, production support commitment, or assurance that a
reported issue will be accepted into the roadmap.

## Choose the right channel

- Use [GitHub Discussions](https://github.com/redxking/evidence-state-io/discussions) for
  questions, interpretation, early design ideas, and research conversation.
- Use a structured [issue](https://github.com/redxking/evidence-state-io/issues/new/choose)
  for a reproducible defect, research-gap hypothesis, benchmark case, or bounded feature
  proposal.
- Follow [SECURITY.md](SECURITY.md) for vulnerabilities, exploit details, sensitive data,
  credentials, or private-system information. Do not place them in public channels.

Search existing issues and discussions before opening a new item. Include the package
version, full Git revision, supported Python runtime, operating system, installation path,
minimal public-safe reproduction, expected result, actual result, and exact checks already
run. State any unavailable evidence or blocked validation explicitly.

## Supported boundary

Community support covers local evaluation with synthetic, public-safe, or explicitly
approved nonsensitive data on Python 3.11, 3.12, and 3.13. Optional VM and container-lab
work remains bounded by the repository's documented loopback and synthetic-data controls.

The project does not currently support production operations, safety-critical or
consequential decisions, sensitive-data workflows, autonomous investigation closure,
authenticated source attestations, or incident response for third-party systems. A local
test result or certificate is not proof of source truth, authorization, compromise,
security, or production fitness.

## What to expect

Maintainers may ask for a smaller reproduction, a matched control, an independent oracle,
or a clearer claim boundary before triage. Priority is based on safety impact, roadmap fit,
reproducibility, and available capacity. Lack of response is not acceptance, rejection, or
validation of a claim.
