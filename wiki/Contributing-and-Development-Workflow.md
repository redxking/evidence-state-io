# Contributing and development workflow

Start with a bounded issue linked to a requirement or acceptance criterion.
Use a feature branch, preserve fail-closed semantics, add negative and
adversarial tests, run the full applicable gate, sign commits with the DCO, and
submit a pull request using the checklist. Contract changes require an ADR and
version analysis.

Questions and research hypotheses belong in Discussions; reproducible defects
and bounded work belong in Issues; vulnerabilities use private reporting. See
[CONTRIBUTING.md](https://github.com/redxking/evidence-state-io/blob/main/CONTRIBUTING.md)
and the [code of conduct](https://github.com/redxking/evidence-state-io/blob/main/CODE_OF_CONDUCT.md).
